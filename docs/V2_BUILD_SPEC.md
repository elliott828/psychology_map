# Psychologymap v2 执行规格

本文件把 `psychologymap-v2-framework.md`（知识结构与数据格式）落成可执行的两项工作：**A 补全并核对数据**，**B 写出正式页面**。两项工作由不同的执行者同时进行，互不修改对方的文件。与框架文件冲突时，以框架文件为准；认为规格有错时在汇报中指出，不要自行改变设计。

视觉基准是 `psychologymap-v2-preview-fx.html`（强视效版）。它的配色、字体、发光、沙漏几何、群山画法、悬停聚焦、手机卡片都已被采纳，正式页面在它的基础上扩展，不重新设计。

## 0. 文件与边界

```
data/psychologymap-data.js     数据（A 负责；B 只读）
data/validate.js               数据校验（A 负责）
data/verification-log.md       核对记录（A 新建）
src/styles.css                 样式（B）
src/app/*.js                   页面逻辑，按文件名顺序拼接（B）
src/index.template.html        页面骨架（B）
build.js                       把模板、样式、脚本、数据拼成单个文件（B）
test/smoke.js                  冒烟测试（B）
psychologymap-v2.html          构建产物：单文件，零外部请求（B，由 build.js 生成）
```

- 不修改上表以外的任何文件，包括旧的 `psychologymap-expanded.html` 和两个预览页。不提交 git。不启动本地服务器。
- 不用任何框架、打包器或第三方库。原生 HTML / CSS / JS，Node 24 只用于构建和测试。
- 产物必须是单文件：页面要能以 `file://` 打开，也要能在不加载外部脚本的沙箱预览里运行，所以样式、脚本、数据全部内联。

## A. 数据补全与核对

### A1. 补齐覆盖

现状（122 个学派）：24 个没有理论，24 个没有人物，68 个没有概念卡，52 个没有书。目标：

| 每个学派至少有 | 已成型（99） | 进行中（23） |
|---|---|---|
| 理论 | 1 | 1 |
| 人物 | 1 | 1 |
| 概念卡 | 1 | 0（有合适的就写） |
| 书或文献 | 1 | 1（可以是标志性论文，`role:'reference'`） |

- 每条脉络的概念卡不少于 8 张，书不少于 12 本。
- 每本书尽量挂到具体理论（`theories`）；每位人物至少属于一个学派。
- 所有节点都有 `title.en`。
- 20 个源头各补一个 `people`（可空数组）和一句"它今天还在哪里出现"（新字段 `legacy:{zh}`）。
- 把这些覆盖要求写进 `validate.js`，跑到通过为止。

### A2. 核对事实

目前 246 条为 medium、28 条为 low，且此前没有联网核对。按下面的优先级逐条核对，能联网就联网查（只发通用检索词，不要把本项目或其所有者的任何信息发给外部服务）：

1. 学派、源头、关系：标志年、标志事件、关系的方向与理由。
2. 理论：年份、提出者归属。
3. 书：原书名、作者、初版年份；中文书名只在确认有该译本时保留，否则 `title.zh` 用直译并在 `summary` 末尾注明"暂无通行中译名"。查不到存在证据的书删除，并在记录里说明。
4. 人物：生卒年。查不到就保持 `null` 和 `low`，不要估计。
5. 证据状况（`evidence`）的档位是否与 `evidenceNote` 的说法一致。

核对后把 `confidence` 改为相应的档位，并在 `data/verification-log.md` 里记一行：节点 id、核对了什么、结论、依据（来源名称与网址）。改动了事实的条目单独列一节。框架骨架里的年份如果查出有误，改数据里的值，同时在记录最前面的"与框架不一致"一节列出，供设计者改框架。

### A3. 不要做的事

不新增脉络；不改学派 id；不删骨架里的学派和关系；不调整数据格式（新增字段只限本节写明的 `legacy`）。影响分的上限（5 分 ≤ 15%，4–5 分 ≤ 40%）继续成立。

## B. 页面

### B1. 结构与构建

- `build.js`：读模板，把 `src/styles.css`、`src/app/*.js`（按文件名排序）和 `data/psychologymap-data.js` 内联进去，写出 `psychologymap-v2.html`。数据文件解析失败时报错退出并保留上一次的产物（另一位执行者同时在改数据，可能读到写了一半的文件，重试即可）。
- 建议的脚本拆分：`00-data.js` 适配与索引，`10-state.js` 状态与路由，`20-ridge.js` 群山，`30-glass.js` 沙漏，`40-thread.js` 脉络详情，`50-panel.js` 详情栏，`60-structure.js` 结构，`70-people.js` 人物，`80-questions.js` 问题，`85-reading.js` 阅读，`90-search.js` 搜索，`95-mobile.js` 手机布局，`99-main.js` 启动。可以调整，但每个文件只管一件事。
- 数据适配层一次性建好索引：按 id 取任意节点；学派 → 理论／人物／概念／书；人物 → 学派／理论／书；理论 → 概念／书；关系拆成"学派之间"和"理论层"两组；源头的 `to` 视作类型为 `feeds`（流入）的关系。页面其余部分只通过适配层取数。
- 高度模型沿用预览：每个学派在登场年前后按高斯核计入（`exp(-d²/72)`），已成型的按影响分折算权重 `[_, .45, .7, 1, 1.5, 2.2]`，进行中的权重为 1。

### B2. 导航

顶栏五个入口：**脉络 · 结构 · 人物 · 问题 · 阅读**。手机上改为底部标签栏，同样五项。当前位置用面包屑显示在次级栏：`全景 › 无意识与深度 › 客体关系`，每一级可点。

路由全部走 URL hash，刷新和分享后能回到同一状态：

```
#/map                    脉络 · 沙漏入口
#/map/ridge              脉络 · 群山
#/map/t/<threadId>       脉络详情
#/structure  #/people  #/questions  #/questions/<id>  #/reading
?n=<nodeId>              任何视图下打开某个节点的详情栏
?c=<idA>,<idB>           对比
```

### B3. 脉络

**沙漏（入口）**：照预览实现，改两处。
- 光粒子减弱：数量降到桌面约 160、手机约 90；透明度降到现在的四成左右；尺寸 0.6–1.1px；速度降到六成；瓶颈光核不再明显脉动。粒子应当是"仔细看才注意到"的程度，不能抢过标签。
- 学派与源头的数量、评分改用正式数据。

**群山**：照预览实现，另加：
- 筛选条（在次级栏）：证据状况（六档，多选）、活动类型（五种，多选）。不匹配的节点淡化，不移除。
- 点左侧脉络名进入该脉络的详情视图。

**脉络详情**（新）：一条脉络的放大视图，是原来"中层"的位置。
- 上方：这条脉络的山脊，横向铺满，所有学派都有标签。
- 下方：与山脊共用同一条时间轴。每个学派一列，学派名下面按年份排列它的理论（小圆点加名称），理论旁列出提出者。脉络内部的关系画成连线；通向别的脉络的关系写成学派旁的标签（如"→ 汇流 · 临床 · 认知行为治疗的整合"），点标签跳到对方。
- 左右方向键或顶部的脉络切换条在九条脉络之间移动。流入这条脉络的源头列在最左边。

### B4. 详情栏

右侧抽屉（手机为底部抽屉，高度约七成屏，可下拉关闭）。栏内可以连续跳转，带"返回"按钮；打开的节点写入 `?n=`。置信度不是 high 的节点在标题旁标"待核对"。各类型的内容：

- **学派**：脉络色块与名称、状态（进行中）；中英文名；标志年与事件；一句话主张；三项评分（历史影响 1–5 的刻度，进行中的不显示并说明原因；证据状况的档位加一句说明；大众知名度 1–5）；理论列表；人物；概念卡（白话定义、生活例子、常见误用，默认只展开第一张）；关系（类型、方向、对方、理由，按类型分组）；阅读阶梯（入门 → 进阶 → 深读，标明读物类型）；与它有关的问题、争论、误读。
- **理论**：所属学派、年份与标志事件、提出者、主张、三项评分、相关概念、相关的书、理论层的关系。
- **人物**：中英文名、生卒年、一句话身份、所属学派、提出的理论、写的书。
- **概念**：白话定义、生活例子、常见误用、所属学派。
- **书**：书名（中、英）、作者、年份、读物类型、难度、它讲的学派和理论。
- **源头**：年代说法、一句话、流入哪些脉络、直接流向的学派、今天还在哪里出现。
- **应用分支**：领域、标志事件、哪些理论被用在这里。

**对比**：详情栏里有"对比"按钮，再选第二个学派后，底部升起对比条，并排显示两者的标志年、主张、三项评分，以及它们之间的直接关系（没有就写"骨架里没有直接关系"）。

### B5. 结构

回答"今天的心理学由哪些部分组成"。四行（生物／个体心智／关系／社会文化）乘五列（理论／基础研究／临床／方法／应用）的矩阵。每格里是学派的小标签，左边带脉络色块，按影响分排序，进行中的用虚线边框。悬停一个学派，同一脉络的其他学派在所有格子里一起高亮。格子右上角显示数量。手机上改为按行折叠的列表。

### B6. 人物

回答"这些思想是谁提出的"。横轴是年份，每位人物一条从出生到去世（在世的到今天）的细线，线上标出他提出各理论的年份。按脉络分九个泳道，泳道内按出生年排列并自动错行避免重叠。出生年未知的人物列在右侧"生年待考"一栏。顶部可切换排序：年代／影响（一个人的影响 = 他提出的理论的影响分之和）。可按脉络筛选。手机上是按脉络分组、按出生年排序的列表。

### B7. 问题

三个页签：
- **生活问题**（12 个）：卡片网格。点开一个问题，把几种解释并排显示，每种解释标出它来自哪条脉络、哪个理论或概念，点击进入对应详情。这是面向爱好者最重要的入口，并排比较必须一屏内看得到至少三种解释。
- **争论**（10 场）：按年份排列，每场列出各方立场与一段经过。
- **流行误读**（10 条）：说法、结论（一个醒目的标签）、更正、相关节点。

### B8. 阅读

所有的书，按脉络分组。筛选：难度（入门／进阶／深读）、读物类型。每条显示作者、年份、类型、难度和一句介绍，点击进入书的详情。顶部给一个"从这里开始"：每条脉络难度为入门的第一本。

### B9. 搜索

搜索所有类型的节点和 12 个问题，匹配中文名、英文名、id、人名。结果按类型分组，最多每组 5 条，上下键移动、回车打开、Esc 关闭。

### B10. 手机（宽度 ≤ 760px）

- 脉络：沙漏照预览；"展开"后是山脊卡片（预览已有），点开一条脉络是纵向的学派列表，每个学派可再展开看它的理论。
- 不出现横向滚动条。可点区域不小于 44px。正文不小于 13px，标签不小于 12px。
- 详情用底部抽屉；对比在手机上改为上下两栏。

### B11. 通用要求

- 界面文字全部中文；英文名作为副标题显示并参与搜索。
- 文字颜色只用墨色的几个层级，不用脉络色；脉络色只出现在色块、线和填充上。
- 所有可交互元素可用键盘到达并有可见焦点；图形元素带 `aria-label`。
- 系统开启"减少动态效果"时：关闭粒子、自动旋转、展开动画和脉冲。
- 窗口尺寸变化用 `ResizeObserver` 重排，不依赖定时器。
- 页面打开后不发任何网络请求。

### B12. 验收

`test/smoke.js`（Node 直接运行）至少检查：
1. `build.js` 成功，产物里没有 `http://`、`https://` 开头的资源引用，也没有 `src=`、`href=` 指向外部文件。
2. 适配层：每个节点能按 id 取到；每个理论的学派存在；每条关系两端存在；每个问题的每种解释指向的节点存在。
3. 产物内每段 `<script>` 语法正确。
4. 对每一种节点类型各取 3 个，调用详情栏的渲染函数（渲染函数要写成可在 Node 里传入节点、返回 HTML 字符串的纯函数），不抛错且结果非空。
5. 路由解析：上面列出的每种 hash 都能解析成状态，再序列化回同一个 hash。

如果环境里有浏览器工具，另外实际打开产物，在 1280×800 和 390×800 两个尺寸下把五个入口各走一遍，确认控制台没有报错，并在汇报里说明看了什么。没有浏览器工具就明确写"未做浏览器实测"。
