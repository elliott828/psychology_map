## 1. 数据修订（D）

### 1.1 荣格的影响线

分析心理学在学派层被低估，原因是它对其他脉络的影响没有录入。逐条核对出处后录入；每条在核对记录里写明来源。只有目标节点确实存在或值得新建时才加关系，否则写进相关理论的 `summary`。

- **外向与内向 → 人格的因素模型。** 这对术语出自《心理类型》（1921），艾森克沿用并改造成可测量的维度。从理论 `psychological-types` 到学派 `factor-personality`，类型 `bridges`。大五的"外向性"经由因素模型继承，不必另加一条。
- **心理类型 → MBTI。** 新建理论节点 MBTI（迈尔斯—布里格斯类型指标），如实标注：大众知名度 5，证据状况按现有"流行误读"条目的结论填写。挂在"个体差异与测量"脉络里最合适的学派下，并说明理由。从 `psychological-types` 到它，类型 `develops`。现有的"大五批评心理类型"保留。
- **人生阶段 → 毕生发展。** 荣格 1930 年前后论"人生的阶段"与中年转折，是成人发展研究的早期来源之一。新建理论节点挂在 `analytical-psychology` 下，连到学派 `lifespan`，类型 `bridges`。
- **积极想象 → 沙盘游戏。** 新建理论节点"积极想象"挂在 `analytical-psychology` 下，连到已有的理论 `sandplay`，类型 `develops`。
- **分析心理学 → 戒酒互助会。** 荣格对病人罗兰·哈泽德的建议，经比尔·威尔逊记述，是互助会创立的源头之一。连到应用节点 `app-self-help`，类型 `applies`。
- **词语联想实验与皮肤电。** 1907 年前后荣格用检流计记录联想时的皮肤电变化。没有合适的目标节点，写进理论 `word-association`（或现有对应 id）的 `summary`，并确认"情结"有概念卡。

`analytical-psychology` 的 `influence` 由 3 改为 4。改后 4—5 分占比仍须不超过 40%，校验必须通过。

### 1.2 每个学派的代表人物与代表作

给每个学派加两个字段，页面用它们在地图上做标注：

- `keyPerson`：一个人物 id。取与该学派标志事件直接相关的那个人；标志事件涉及多人时取通常被首先提到的那位。
- `keyWork`：一个书或文献 id。取标志事件对应的那部著作；没有对应著作时取该学派里最常被引用的一部。

两者都必须指向已存在的节点（没有就先补节点）。校验脚本检查这两个字段。

### 1.3 每个理论都有可读的书

阅读路径（第 6 节）要求从任何一个理论出发都能给出书。为此：

- 每个理论至少被一本书或文献的 `theories` 引用。先把现有的书挂到它们实际讲到的理论上；确实没有的再补书。
- 每本书补全以下字段：
  - `lang`：原著语言（`en`、`zh`、`de`、`fr`、`ja` 等）。
  - `original`：`{ title, author, year }`，原著的原文书名、作者原名、初版年份。
  - `enRec`：推荐给英文读者的版本，`{ title, author, edition, year, note }`。原著是英文的，推荐一个通行、易得的版本（如周年纪念版、修订版）；原著不是英文的，推荐公认的英译本并写明译者；没有英译本的写 `null`。`note` 用一句话说明为什么推荐这个版本。这是编辑推荐，不需要评分依据，但版本必须真实存在。
  - `zhQuery`：用来在豆瓣检索中文版的检索词（通常是中文书名加作者中文名）。原著是中文的直接用书名。没有中译本的写 `null`。
  - （订正）豆瓣的检索建议接口只按书名匹配，带上作者会查不到。抓取脚本只取 `zhQuery` 里的书名部分去检索，作者留给匹配步骤用来分辨同名书。
- 不要填豆瓣链接和评分，那由管线抓取（第 5 节）。

校验脚本增加：每个理论至少一本书；每本书有 `lang`、`original`，且 `enRec` 与 `zhQuery` 两个键都存在（值可以是 `null`，但不能两个都是 `null`）。

## 2. 双语界面（P）

- 界面语言有英文和中文两种，**默认英文**。顶栏右侧放语言切换（`EN｜中文`）。选择写入 `localStorage`（读写都包在 try/catch 里，失败时照常工作），并可用 hash 里的 `lang=zh` 或 `lang=en` 指定，便于分享。切换后 `<html lang>` 同步更新。
- 界面文字（导航、按钮、说明、图例、空状态、aria-label）集中在一个词典文件里，两种语言各一份，不在别处写死。
- 内容字段统一成 `{ zh, en }` 的形式，页面用一个取值函数读取：当前语言有就用，没有就退回另一种语言。数据里目前只有 `title` 和人名有英文；其余字段的英文由第二阶段的 `data/en/*.json` 提供，`build.js` 在构建时把它们并入对应字段（文件格式见第 7 节）。译文缺失的字段在英文界面下显示中文原文，不留空。
- 英文标签比中文长。地图上的学派标签在英文界面下优先用 `title.enShort`（第二阶段提供，不超过 18 个字符），没有就用 `title.en`；标签宽度估算要按拉丁字符处理，避让算法照旧。任何标签不小于 12px。
- 英文界面下人名用 `name.en`，书名用 `enRec.title`（没有则 `original.title`）。中文界面下反之。详情栏里两种语言的名称都显示，当前语言在上。
- 搜索在两种语言下都同时匹配中英文名。

## 5. 抓取管线（T）

目的：给每本书配上中文版的豆瓣链接与评分，以及英文版的公开书目链接。脚本用 Node 24 自带的 `fetch`，放在 `tools/`，ESM 写法（仓库的 package.json 是 `"type":"module"`）。

### 5.1 分两步，中间落盘

1. **抓取**（不需要语言模型）。`node tools/fetch-books.mjs`
   - 对每本 `zhQuery` 非空的书，请求豆瓣的检索建议接口 `https://book.douban.com/j/subject_suggest?q=<检索词>`，得到若干候选（同一本书的不同版本通常都在里面）。
   - 对前 5 个候选逐个请求条目页 `https://book.douban.com/subject/<id>/`，从页面里取：书名、副标题、作者、译者、出版社、出版年、ISBN、评分、评价人数。
   - 对每本 `enRec` 非空的书，请求 Open Library 检索 `https://openlibrary.org/search.json?title=..&author=..&limit=5`，保存候选（work key、标题、作者、首版年、版本数）。
   - （订正）Open Library 的检索对完整副标题和作者全名过于严格：标题只用冒号前的主标题，作者只用姓。
   - 原始结果按书的 id 存进 `data/cache/`，已有缓存的跳过，可随时中断重跑。
2. **匹配**（交给 DeepSeek）。`node tools/match-books.mjs`
   - 对每本书，把它的 `original`、`enRec`、`zhQuery` 和缓存里的候选一起发给 DeepSeek，让它判断哪些候选确实是同一部著作的中文版（作者译名、书名变体、合订本与节选本都要分辨），哪个 Open Library 条目是这部著作。要求返回 JSON，并给出简短理由。
   - 版本选择由脚本按规则做，不交给模型：在被判定为同一部著作的中文版里，取评价人数不少于 30 的版本中评分最高的；都不足 30 人就取评价人数最多的；并列时取出版年较新的。其余版本最多保留 2 个作为备选。
   - 写出 `data/book-links.json`。

### 5.2 输出格式

```json
{
  "<workId>": {
    "zh": { "title": "", "author": "", "translator": "", "publisher": "", "year": 2012,
            "doubanId": "10785583", "url": "https://book.douban.com/subject/10785583/",
            "rating": 8.1, "votes": 51234, "alt": [ { "title": "", "publisher": "", "year": 2025, "url": "", "rating": 8.6, "votes": 412 } ] },
    "en": { "title": "", "author": "", "openLibrary": "https://openlibrary.org/works/OL...W", "firstPublished": 2011 },
    "matchedBy": "deepseek-chat", "matchNote": "", "fetchedAt": "2026-11-15"
  }
}
```

没匹配到的一侧写 `null`。页面只读这个文件，不读缓存。

### 5.3 约束

- **守规矩地抓。** 请求之间至少间隔 2.5 秒，单线程。`User-Agent` 用如实的通用名称 `psymap-book-lookup/0.1`，不伪装成浏览器。遇到 403、418、429、验证码页或登录页就停下来，把已得结果落盘并在汇报里说明，不要想办法绕过。
- **密钥。** DeepSeek 的密钥只从环境变量 `DEEPSEEK_API_KEY` 或 `tools/.env` 读取（`tools/.gitignore` 把 `.env` 和缓存目录排除在外，另放一份不含密钥的 `tools/.env.example`）。密钥不写进代码、日志、缓存或汇报。没有密钥时，匹配脚本打印一句说明后正常退出，不报错。
- **只发公开的书目信息。** 发给 DeepSeek 和 Open Library 的内容仅限书名、作者、候选条目，不包含本项目或其所有者的任何信息。
- 接口：`https://api.deepseek.com/chat/completions`，模型 `deepseek-chat`，`response_format` 用 JSON。失败重试最多 3 次，带退避。

### 5.4 本阶段要做到哪一步

写好两个脚本和一个不联网的自测（用一份手工构造的候选缓存，检验版本选择规则和输出格式）。然后对数据里现有的书实际跑一遍**抓取**，把缓存填上。**匹配**这一步现在没有密钥，跑不了：确认它在无密钥时正常退出即可。数据那边同时在给书补 `zhQuery` 和 `enRec`，补完之前这两个字段可能还不存在：抓取脚本对缺字段的书退而用 `title.zh` 加作者做检索词，并在缓存里记下用的是哪个检索词，以便之后重跑时识别。

## 6. 阅读路径（P）

回答"读懂这个理论，之前该读什么，之后可以读什么"。

- **在哪里出现。** 理论和学派的详情栏里各加一节"阅读路径"；"阅读"页顶部加一个入口：搜索并选定任一理论或学派，展开它的路径。路由 `#/reading/path/<nodeId>`。
- **上下游怎么定。** 写成适配层里的纯函数，可在 Node 里测试：
  - 上游：指向该理论的理论层关系的来源；没有则取指向它所属学派的学派层关系的来源，以及流入该学派的源头。类型为 `reacts` 的，上游是它反对的对象，标注"它反对的"。按年份排序，最多 3 个。
  - 下游：从该理论或其学派出发的关系的目标；指向它的 `critiques` 也算下游，标注"后来的批评"。按年份排序，最多 3 个。
  - 每个上下游节点取 1 本书：优先 `theories` 里引用它的，其次是它所属学派的；多本可选时优先难度为入门的，再按豆瓣评分高的。
  - 本节点自己给出阅读阶梯：入门、进阶、深读各最多 1 本。
- **怎么显示。** 三段横排（手机上竖排）：**先读｜这个理论｜接着读**，段与段之间用箭头连接，每本书标出它对应哪个节点、与本节点是什么关系。每本书显示：
  - 当前语言的书名、作者、年份、难度；
  - 中文版：豆瓣评分与评价人数、出版社与年份、"豆瓣"链接；有备选版本时折叠显示；
  - 英文版：推荐版本与一句理由、Open Library 链接；
  - 某一侧没有（如无中译本）就如实写"暂无中译本"或"No English edition"。
- 外链用 `target="_blank" rel="noopener"`。这是页面里唯一的外部链接，只有用户点击才会访问；页面本身仍然不发任何网络请求。冒烟测试里"产物无外部引用"的检查相应放宽为：允许 `<a href>` 指向 `book.douban.com` 和 `openlibrary.org`，其余照旧。
- 书的详情栏里同样显示两种版本的信息与链接。

## 7. 第二阶段（第一阶段交回后另行安排，这里只定格式）
